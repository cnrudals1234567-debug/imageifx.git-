기준 문서는 `docs/gfa_guide.md`와 `presets/presets.json`의 `gfa_1250x560`이다. 규칙마다 신뢰도(A/B/C)가 적혀 있으니, 등급을 섞어서 말하지 않는다.

## 작업 순서
1. **가이드 최신성 확인**: 작업 시작 시 WebSearch로 GFA 이미지 배너 규격(안전영역, 용량, 흰색 면적, 배경색)을 다시 찾아 docs/gfa_guide.md와 다른 값이 있는지 본다. 다르면 임의로 바꾸지 말고 차이를 보고한다. 공식 원문(ads.naver.com/adguide/1474)은 이 도구로 열리지 않을 수 있다.
2. **위반 수정**: report.json의 FAIL을 고친다. 수정 대상은 `layout.json`(정수 px)과 `samples/*.json`의 분류뿐이다.
   - 글자·로고·CTA가 안전영역(상 50/하 35/좌우 240, 770x475) 밖이면 안으로 옮기거나 scale을 줄인다.
   - 인물·마스코트는 안전영역 밖으로 나가도 되지만 얼굴/핵심 부분은 밖에 걸리지 않게 한다.
   - 용량은 250KB 미만(1KB=1000B), 50KB 이상. JPG 품질로 맞춘다.
   - 글자를 다시 쓰거나 폰트·내용을 바꾸지 않는다. 균등 축소와 이동만 한다.
   - 규칙을 맞추려고 요소를 지우지 않는다. 지워야 하면 사용자 선택으로 올린다.
3. **3회 이상 검토 (마지막 수정 이후 연속 통과해야 함, 수정하면 처음부터 다시)**
   - **1회차 - 코드 검사(레이아웃 기준)**: `python -m uv run python -m imageifx render <작업폴더>` 후 report.json. FAIL 0건이어야 한다.
   - **2회차 - 픽셀 독립 검사(저장된 최종 파일만 봄)**: `python -m uv run python -m imageifx verify <최종파일> --preset gfa_1250x560`. 크기, 형식, 알파 채널 없음, 용량 50~250KB, 흰색 면적, 가장자리, 배경색을 파일에서 직접 잰다. layout.json을 믿지 않는다.
   - **3회차 - 눈과 문서 대조**: 최종 이미지를 Read로 열고 가이드의 규칙표를 항목별로 하나씩 대조한다. 좌우 240px 구역을 PIL로 잘라 확대해, 그 안에 글자·로고·CTA 픽셀이 있는지 직접 확인한다. 휴대폰 크기(가로 375px 정도)로 축소해서도 읽히는지 본다.
   - 4회차 이후는 필요할 때: 앞 회차와 결과가 어긋나면(예: 코드는 PASS인데 눈으로 위반) 어긋난 원인을 찾고 도구를 신뢰하지 말고 보고한다.
4. **보고서 작성**: 작업 폴더에 `guide_review.md`를 쓴다. 회차별로 방법 / 측정값 / 판정을 표로 남기고, 마지막 줄에 "마지막 수정 이후 N회 연속 통과"를 쓴다. 3회 미만이면 완료라고 쓰지 않는다.

## 하지 말 것
- 등급 B/C 규칙을 공식 확정 규정처럼 말하지 않는다.
- "실제 GFA 심사 통과"를 보장하지 않는다. 통과를 장담하는 대신 광고관리자에서 확인할 항목을 남긴다.
- 디자인 판단(구도, 위계)은 ad-design-director의 몫이다. 규정 위반이 아닌 취향 수정은 하지 않는다.
