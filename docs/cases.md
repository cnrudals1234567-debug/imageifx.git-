# 사례집 (비슷한 문제가 생기면 먼저 여기서 찾는다)

사용자와 함께 푼 실제 사례와 해결 방법. 이미지는 `docs/cases/`, 분석 json은 `samples/`. 새 소재가 아래 "증상"과 비슷하면 "해결"을 먼저 시도하고, **결과 이미지는 반드시 직접 열어 확인**한다(코드 PASS만 믿지 않는다).
날짜: 2026-10-17. 모두 GFA 1250×560 기준.

## 사례 1. 글자가 인물(머리카락) 뒤에 가려져 있었던 경우 (TESOL 대학원)
- **소재**: 보라 단색 배경, 흰 굵은 제목 `TESOL 대학원`, 인물 머리카락이 `O`·`L`·`대` 아랫부분을 덮음. 스타일 `bold_solid`. 분석: `samples/tesol_bold_solid_restore.json`
- **증상**: 글자와 인물을 떼어 놓으면 `O`·`L` 아랫부분이 빈 채 드러나고 머리카락 가장자리의 흰 얼룩이 남는다. 코드 검사는 못 잡는다.
- **원인**: 분해가 인물 아래 글자 픽셀을 지운다(`decompose.py`). 원본에 가려진 픽셀 자체가 없다.
- **해결**: 분석 요소에 `"occlusion": "restore"` → `imageifx/occlusion.py`가 가려진 영역 R만 글자 모양(이진 마스크)을 LaMa로 이어 그린 뒤 R 주변을 이진 글자 모양으로 확정(열기·닫기, 색은 글자색 중앙값). R 밖 글자 픽셀은 그대로. **규칙 1의 예외라 사용자 승인 필요.** 가림 유지(글자+인물 한 묶음 배치)는 인물이 작아져 규정 FAIL 가능성이 커서 만들지 않았다.
- **같이 고친 것**: 학교명 22px 미만 → `bold_solid.text_width_ratio` 0.58. 하단 띠가 흰색이라 "가장자리 흰색" FAIL → `band_tint_ratio` 0.12(배경색을 섞음, 디자인 색 변경이므로 사용자 확인). 알약(칩) 글자 잘림 오탐 → 분석 bbox를 알약보다 4px 넓게.
- **결과**: `docs/cases/tesol_occlusion_restored.jpg` (이전: `tesol_occlusion_before.jpg`). 복원 `O`·`L` 아랫선이 확대하면 약간 울퉁불퉁.
- **주의**: 가림 감지가 하단 안내문(`recruit`)을 오탐함 → 복원은 사용자가 요소별로 지정한 것만 한다.

## 사례 2. 사진 위에 글자·붓터치·효과가 얹힌 소재 (영월 당일투어)
- **소재**: 하늘 사진 위 흰 제목, 노란 붓글씨 `3만원`, 낙서(비행기·구름), 인물, 풍경. 분석: `samples/yeongwol_photo_whole.json`(글자 3개만 critical)
- **증상(분해 방식)**: 글자를 `bbox`로 떼면 하늘·구름·붓터치가 사각형째 딸려 오고, 흰 스크림이 뿌연 막이 되고, 글자 상자끼리 겹쳐 서로 잘리고, 장식 잔해가 남고, 풍경이 사라진다. 이전 결과: `docs/cases/yeongwol_decompose_before.jpg`
- **원인**: 소재 자체가 레이어 분해에 맞지 않는다(글자가 사진 픽셀과 섞여 있음).
- **해결**: 스타일 `photo_whole`. 글자를 떼지 않고 원본 전체를 균등 축소(`fit_ratio`)해 글자 묶음을 안전영역(770×475)에 넣고 가장자리만 확장. 글자 레이어는 검사용(`ghost`)이며 합성하지 않아 글자 픽셀이 한 장도 바뀌지 않는다. 결과: `docs/cases/yeongwol_whole_final.jpg`
- **배율 선택**: 0.70배 = 얼굴만 보임, 0.59배 = 풍경이 보이나 오른쪽 AI 확장 420px, 0.65배(`fit_ratio` 0.93) 채택.

## 사례 3. 배경 확장이 흐리거나 줄무늬가 생길 때 (영월 오른쪽·왼쪽 확장)
| 증상 | 원인 | 해결(코드) | 이미지 |
|---|---|---|---|
| 풍경(산·숲)이 뭉개져 흐림 | LaMa가 새로 그린 부분은 매끈해진다 | 글자 없는 풍경 구간은 **원본 가장자리 기준 좌우 반사**(`fill.mirror_right`, 확장이 넓으면 왕복). 실제 원본 픽셀이라 선명 | `yeongwol_lama_haze_before.jpg` |
| 하늘에 **세로 물결 줄무늬** | 한 번에 넓게 채우거나 96px 단계 경계마다 LaMa 결과가 어긋남 | 하늘 구간은 AI 대신 **하늘 색 프로필 + 입자 잡음**(`fill.sky_right`): 행별 파란 하늘 색, 경계 색차는 멀어질수록 0, 구름은 약 20px 안에 흐려져 사라짐 | `yeongwol_lama_streaks_before.jpg` |
| 반사에 인물 손이 복제돼 분홍 조각 | 반사 범위에 손이 포함 | `mirror_src_x0`로 손 왼쪽 열 제외, 낙서 구름 아래부터 반사(`mirror_gap_px`) | |
| 위쪽 빈 띠가 검게 남음 | 옆 확장을 먼저 하면 검은색이 맥락이 됨 | 원본 열의 위/아래 빈 띠를 먼저 채운 뒤 옆으로(`fill.outpaint_progressive`) | |
| 하늘 쪽에서 수평 번짐(줄) | 가장자리 구름·반짝이가 프로필에 섞임 | 하늘색만 골라 평균(붉은 기가 낮은 픽셀), 큰 차이는 짧게 감쇠 | |
- **남은 한계**: 하늘이 매끈해 오른쪽이 약간 평평하고, 원본 오른쪽 끝에서 약 868px 지점에 옅은 이음선이 남는다. 반사는 글자가 없는 구간에서만 쓸 수 있다(글자가 뒤집혀 복사됨).
- **왼쪽 확장**(54px 안팎, 인물이 가장자리에 걸린 경우): 반사하면 머리카락·팔이 대칭으로 보이므로 단계적 LaMa를 쓴다.

## 일반 원칙 (사례에서 얻은 것)
1. 글자 픽셀을 건드리지 않는 쪽이 항상 먼저다: 소재가 분해에 안 맞으면(사진 위 글자) 떼지 말고 원본 통째 유지를 먼저 고려.
2. 확장은 "AI 한 번에 크게"가 아니라 ① 원본 실제 픽셀(반사) ② 색 모델+입자(하늘·단색) ③ 단계적 LaMa(나머지) 순으로 고른다. AI는 질감이 있는 곳에서 흐려진다.
3. 새 방식은 `layout.json`의 bg 키(`outpaint`, `mirror_below_src_y`, `mirror_src_x0`, `sky_right`)나 요소의 `occlusion`일 때만 동작하게 해 기준 디자인(테솔·한국어학과 md5)이 바뀌지 않는다.
4. 대비를 키워 확대해 보면 줄무늬·이음선이 잘 드러난다(`(a - 평균) * 4 + 128`). 눈으로 의심되면 이렇게 확인한다.
5. 코드의 "모두 통과"는 줄무늬·이음선·복제 조각을 못 잡는다. 사례마다 이런 결함이 눈으로 발견됐다.
